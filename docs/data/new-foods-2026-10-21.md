# New foods, 21/10/2026

For Hao's server import (Dong's importer, unchanged). Data only: `docs/data/new-foods-2026-10-21.json`, 18 rows, every one new (no live row is updated). One small web commit adds the `fortify_kitchen` source code and the "Fortify Kitchen" tag (`lib/source-names.ts`, test in `lib/__tests__/food-source.test.ts`, gate:fast green on port 3105). No migration, API or database change was made, and nothing was imported.

Values are copied from the USDA FoodData Central CSVs in `food-research/usda` (SR Legacy 2018-04, Foundation 2026-04-30), the NIN table and product labels, and rounded as in `round_nutrients.py` (energy, protein, carbs, fat, fiber to 1 decimal; every other nutrient to 3 significant figures). A nutrient a source does not have is left out, never 0 or null. Values are per 100 g. What is estimated is listed row by row under Flags.

The live catalogue was read on 21/10/2026 from `GET /api/v1/foods` on lehongkhanh.vn: 1,281 foods in 3 pages (`limit=500`; page 4 is empty). Each row below was looked up there under its name and its `source` + `source_id` before it was added: none exists, so the importer's upsert only inserts. Existing rows that look related are kept as they are: Chanh ta (NIN 5003), Chanh dây (FDC 169108), Tỏi (FDC 169230), Bột cacao không đường (FDC 169593).

## Minh Hào rows (Fortify Kitchen)

Brand "Fortify Kitchen", source `fortify_kitchen`, text "Công thức riêng của Fortify Kitchen; giá trị tính từ nguyên liệu (USDA/NIN/nhãn sản phẩm)". The recipes are private and stay outside the repo: this file, the JSON, the commits and the PR carry only the final values per 100 g and the portions, no ingredient list, amounts or method. They are plain foods with no dish parts (no Thành phần, nothing editable).

- **Category `mon_viet`, not `dam`.** The edible-part rule (`scripts/edible-part.ts`) strips every count portion from a `dam` food whose name starts with má đùi gà or tôm, and "1 phần lẻ (200 g sống)" is not a weight label, so it would go; and the raw/cooked switch (`lib/yield`) treats every `dam` row as a raw cut and offers a cooked twin. `mon_viet` (a dish) is exempt from both, and no raw row exists for these, so nothing groups. Hao can say if he wants `dam`.
- **Raw weight.** The five meat and prawn rows are per 100 g of RAW meat as the menu weighs it, so a portion's grams are the raw weight ("1 phần lẻ (200 g sống)" for má đùi, 150 g for the others); their tip says so.
- **Source code.** The importer takes any source string and `lib/source-names.ts` had no code for an own-brand recipe (`recipe_calc` is Ước tính, amber), so `fortify_kitchen` → "Fortify Kitchen" was added in its own commit.
- **Twin and yield code.** `mon_viet` rows are dishes with no state (`lib/food-twins.ts`), so none of the eight groups with another row.

## Chanh juice rows: portion filter check

Hao's decision: juice by quả, an exception to grams-only fruit. Checked, and no web change is needed:

- `weighedFruit` (`lib/mock/foods.ts`) strips count portions only when `category === "trai_cay"`; the four rows are `gia_vi`.
- `edibleKind` / `edibleServings` (`scripts/edible-part.ts`, used by the data scan) returns `fruit` for `trai_cay`, otherwise matches the name against a list of foods sold with a peel, shell or bone (it starts with chuối, dừa, tôm, cua...): "Nước cốt chanh..." and "Ruột chanh dây" match none, so `1 quả (nước cốt)` and `1 quả (ruột + hạt)` stay.
- `lib/food-twins.ts` / `lib/yield.ts`: no sống/chín word in the names, and `gia_vi` is not a raw/cooked category, so no twin and no switch.
- The new rows use `source_id` suffixes (`:nuoc-cot-chanh-ta`...), so they cannot overwrite the live Chanh dây (FDC 169108) or Chanh ta (NIN 5003) rows, which stay as they are (logged by grams).
